# 应急预案与故障排查指南

适用对象：信息中心、项目运维人员、联合试点支持人员。

目标：在联合试点正式验收期间，快速定位登录、服务、数据、导入、导出、AI/OCR/连接器和误传数据问题，保护数据安全并恢复业务验证。

## 1. 应急分级

| 等级 | 场景 | 响应目标 |
| --- | --- | --- |
| P0 | 服务不可用、数据库损坏、真实敏感数据误传、密封包大面积校验失败 | 立即暂停相关操作，30 分钟内形成处置方案 |
| P1 | 登录大面积失败、导入主流程失败、报告无法导出、权限异常 | 1 小时内恢复或给出替代验收路径 |
| P2 | 单个样本字段异常、个别任务失败、AI/OCR 不可用 | 不阻断主验收，半日内给出原因和修复建议 |
| P3 | 文档口径、截图补充、培训答疑 | 验收期间滚动处理 |

## 2. 通用处置流程

1. 记录故障时间、操作人、账号角色、任务编号、样本批次和错误截图。
2. 判断是否涉及真实敏感数据、权限越权或导出文件泄露。
3. 如涉及数据安全，立即暂停上传、导出和外发。
4. 检查 `/api/health` 和 `/api/health/details`。
5. 检查启动日志、应用日志和审计日志。
6. 根据场景执行专项排查。
7. 恢复后补充验收截图、日志摘要和处置记录。

## 3. 服务不可用

现象：

- 浏览器无法打开系统。
- `/api/health` 无响应。
- 反向代理返回 502、503 或连接超时。

排查步骤：

1. 确认应用进程是否运行。
2. 确认端口是否与 `runtime.local.json` 一致。
3. 检查反向代理是否转发到正确端口。
4. 检查是否传递 `X-Forwarded-Proto=https`。
5. 查看启动日志是否有配置错误或数据库打开失败。
6. 在服务器本机访问应用端口确认是否为代理问题。

恢复方式：

- 重启应用服务。
- 修正反向代理目标端口。
- 如端口被占用，按部署文档选择可用候选端口。
- 如数据库打开失败，进入数据库恢复流程。

验收替代路径：

- 如短时代理故障但本机服务正常，可在内网临时访问本机地址完成截图；正式验收前仍需恢复 HTTPS 地址。

## 4. 登录异常

现象：

- 所有账号无法登录。
- 个别账号密码错误或被锁。
- 服务重启后用户频繁掉线。

排查步骤：

1. 查看 `/api/health`。
2. 检查审计日志中的登录失败记录。
3. 确认账号角色是否存在。
4. 由 `admin` 重置用户密码。
5. 若服务重启后全部会话失效，检查 `AUDITLENS_SESSION_SECRET` 是否变化。

恢复方式：

- 重置密码并记录操作人和原因。
- 恢复原 `AUDITLENS_SESSION_SECRET`。
- 对本地样例环境可使用管理员恢复工具；正式客户环境需按客户制度审批。

## 5. 权限异常

现象：

- `viewer` 可以创建任务或导出敏感结果。
- `auditor` 无法创建文件审计任务。
- `admin` 无法进入管理后台。

排查步骤：

1. 使用 `GET /api/auth/me` 确认当前角色。
2. 检查账号是否被误配。
3. 清理浏览器会话后重新登录。
4. 检查是否使用了错误环境或旧账号。

处置要求：

- 权限越权属于 P1；如涉及敏感导出，升级为 P0。
- 保存截图和审计日志。
- 验收前必须重新验证权限矩阵。

## 6. 数据库损坏或状态异常

现象：

- 服务启动失败，日志提示数据库错误。
- 任务列表为空或状态异常。
- 写入失败或导出失败。

排查步骤：

1. 停止服务，保留当前 `platform.db` 副本。
2. 检查磁盘空间和目录权限。
3. 尝试使用最近备份恢复到临时目录。
4. 在临时恢复环境执行健康检查和任务抽查。

恢复流程：

```powershell
./scripts/restore-platform-db.cmd .\data\backup\platform-YYYYMMDD-HHMMSS.db .\tmp\restore-drill
```

确认恢复有效后：

1. 停止正式服务。
2. 替换正式 `platform.db`。
3. 启动服务。
4. 执行 `/api/health`。
5. 抽查任务、报告和审计日志。

## 7. 导入失败

现象：

- CSV/Excel 上传失败。
- 中文字段乱码。
- 任务生成后无风险结果。
- 字段映射不符合预期。

排查步骤：

1. 确认文件为脱敏样本。
2. 检查文件编码，建议 UTF-8。
3. 核对样本是否包含关键字段：预算项目、指标文号、项目编号、合同编号、支付单号、凭证号、金额、日期。
4. 检查导入入口和模板是否匹配。
5. 查看错误提示中的 `hint` 和 `expected_schema_url`。
6. 用最小样本重新导入验证。

处置方式：

- 字段缺失：由数据负责人补充样本字段。
- 编码问题：转为 UTF-8 CSV 或标准 Excel。
- 模板错误：选择正确任务类型或导入配置。
- 真实数据误传：立即执行数据误传流程。

## 8. 报告或密封导出失败

现象：

- PDF 生成失败。
- 下载文件为空。
- 密封包校验失败。

排查步骤：

1. 确认当前账号为 `admin` 或 `auditor`。
2. 确认任务详情可正常打开。
3. 重新生成 PDF 或密封包。
4. 对密封包执行校验：

```powershell
cargo run --bin seal-verify -- .\sealed.zip
```

5. 检查磁盘空间、浏览器下载拦截和反向代理文件大小限制。

处置方式：

- 重新导出并重新校验。
- 如仍失败，保留任务 ID、导出时间、错误日志和失败文件。
- 验收期间可先使用 PDF 报告截图替代，密封包验收项待修复后补测。

## 9. AI 不可用

现象：

- AI 分析按钮不可用。
- AI 返回策略禁用。
- AI secret 未配置。

判断口径：

- 政府试点默认 `aiEnabled=false`，AI 不可用不影响主流程验收。
- AI 仅为辅助解释层，不是规则审计、报告导出和整改闭环的前置条件。

排查步骤：

1. 查看 `GET /api/bootstrap` 中 `deployment_policy.ai_enabled`。
2. 查看 `/api/health/details` 的 AI 状态。
3. 如客户已批准启用，检查 `AUDITLENS_AI_API_KEY` 是否注入。
4. 确认管理后台只显示 secret 是否配置，不回显 secret。

## 10. OCR/ASR 不可用

现象：

- 图片证据识别失败。
- 音频识别失败。
- `/health` 本地桥接服务不可用。

排查步骤：

1. 检查本地桥接服务是否启动。
2. 确认端点配置，如 `http://127.0.0.1:8090/ocr` 和 `/speech`。
3. 检查模型文件、Tesseract 或 Whisper 依赖。
4. 检查 `ocrEnabled` 和 `speechEnabled` 策略。

处置方式：

- 重启桥接服务。
- 临时关闭 OCR/ASR，不影响规则审计主流程。
- 对验收必要证据，可改用结构化脱敏文本样本。

## 11. 连接器异常

现象：

- 数据库来源审计失败。
- 连接器凭据不可用。
- 白名单表名被拒绝。

排查步骤：

1. 确认当前账号为 `admin`。
2. 检查连接器 profile 是否启用。
3. 检查凭据是否通过环境变量或密钥管理注入。
4. 确认目标表在白名单模板内。
5. 确认数据库账号为只读权限。
6. 检查网络连通性和防火墙。

处置方式：

- 修正白名单模板或表名。
- 更新密钥注入，不在配置文件写入明文。
- 如客户未批准连接真实系统，使用脱敏文件导入替代。

## 12. 真实敏感数据误传

触发条件：

- 在公网样板环境上传真实政府业务数据。
- 未审批就在试点环境上传真实小样本。
- 样本中包含未脱敏个人信息、供应商敏感信息、涉密项目或完整凭证附件。

处置流程：

1. 立即暂停上传、导出和外发。
2. 记录误传时间、账号、文件名、任务 ID、环境地址和涉及数据范围。
3. 通知客户数据负责人和项目负责人。
4. 删除或隔离误传任务及导出文件，按客户制度执行。
5. 检查审计日志，确认是否发生下载或导出。
6. 如已生成密封包或 PDF，追回并登记。
7. 使用脱敏样本重新执行验收。
8. 形成事件记录，说明原因、影响范围、处置动作和防再发措施。

防再发措施：

- 培训中强调公网样板环境禁止真实数据。
- 导入前由数据负责人签字确认脱敏。
- 样本文件命名带 `desensitized`、`sample` 或客户认可标识。
