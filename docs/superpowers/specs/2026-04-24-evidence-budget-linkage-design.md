# 南京商务局公开预算与采购业务证据联动设计

## 背景

当前 AuditLens 第二阶段已经支持预算任务与采购任务的确定性关联，但现有规则只接受三类精确匹配：

1. `indicator_document_no` 精确匹配
2. `project_catalog_id + budget_unit` 精确匹配
3. `budget_unit + 规范化项目名称` 精确匹配

这套规则适合内部系统导出的标准预算明细，但对中国政府公开数据不够实用。公开预算和绩效材料常见问题是：

- 有预算项目和金额，但没有 `项目库ID`
- 有政策依据或文号，但采购公告中没有对应字段
- 预算项目名与采购项目名存在业务同义关系，而不是字面相同

南京市商务局样本已经证明这一点：

- 采购公告：`2025—2026年度南京市冻猪肉政府性储备项目`
- 预算绩效表：`2025年菜篮子发展专项-肉菜储备`
- 同单位：`南京市商务局`
- 同业务证据：`冻猪肉储备量 = 3000吨`

这类样本在业务上明显相关，但无法通过现有精确规则自动打通。

## 目标

在不破坏现有精确匹配规则的前提下，新增一层“业务证据匹配”能力，用于处理公开预算与采购公告之间缺少主键但存在强业务关联的情况。

设计目标：

- 保留当前确定性精确关联作为最高优先级
- 新增“自动关联”和“候选关联”双层证据匹配
- 在前端明确展示关联模式和证据来源，避免把业务证据关联伪装成主键精确关联
- 继续保留“继续寻找官方主键材料”这条外部数据线，不把规则改造当成替代品

## 非目标

- 不引入 AI 语义匹配
- 不做模糊全文搜索引擎
- 不把任何相似名称都当作可自动关联
- 不修改现有预算/采购任务的基础导入格式
- 不删除或降级现有三条精确匹配规则

- 预算单位：`南京市商务局`
- 项目：`2025年菜篮子发展专项`
- 子项：`肉菜储备`

- 项目：`2025—2026年度南京市冻猪肉政府性储备项目`

### 外部数据线结论

公开网目前已经能证明“同单位 + 同业务 + 同储备对象 + 同数量口径”，但还没有找到能稳定提供 `项目库ID` 或采购侧可直接复用的 `指标文号` 的公开附件。

因此需要两条线并行：

1. 继续寻找更细的官方预算/指标明细
2. 在系统内支持“业务证据匹配”

## 设计概览

预算与采购联动分为四种结果：

1. `exact`
   - 精确匹配成功
   - 直接自动关联
2. `evidence_auto`
   - 无主键，但业务证据分数达到高阈值
   - 自动关联，并明确标注为“证据自动关联”
3. `evidence_candidate`
   - 业务证据分数达到候选阈值但未达到自动阈值
   - 不自动挂接为正式关联，进入候选列表
4. `none`
   - 无关联

## 匹配优先级

匹配顺序固定：

1. `indicator_document_no`
2. `project_catalog_id + budget_unit`
3. `budget_unit + 规范化项目名称`
4. `business evidence scoring`

只要命中前 3 类任意一种，直接视为 `exact`，不再进入证据打分。

## 业务证据评分模型

### 基础原则

- 只在 `budget_unit` 已明确一致时才进入高可信证据匹配
- 关键词必须来自受控词典，不使用自由语义理解
- 证据项是加分制，不做黑盒判断

### 第一版评分项

1. 同预算单位：`+40`
   - 采购单位与预算单位名称规范化后相等

2. 共享业务核心词：`+25`
   - 采购项目名与预算项目名/摘要共享高价值关键词
   - 第一版词典包含：
     - `冻猪肉`
     - `冻牛肉`
     - `肉菜`
     - `储备`
     - `菜篮子`
     - `追溯`
     - `保供`
     - `审计`
     - `绩效`
     - `运维`

3. 摘要/指标命中采购关键约束：`+20`
   - 如预算摘要或绩效指标出现采购关键信息
   - 第一版重点支持：
     - 数量约束，如 `3000吨`
     - 储备对象，如 `冻猪肉`

4. 业务类型一致：`+15`
   - 预算项目与采购项目归属同一受控业务类型
   - 第一版业务类型：
     - `reserve_supply`
     - `information_maintenance`
     - `audit_consulting`
     - `performance_evaluation`

### 阈值

- `>= 80`：`evidence_auto`
- `60 - 79`：`evidence_candidate`
- `< 60`：`none`

### 南京商务局样本的预期得分

- 同单位：`+40`
- 共享关键词：`冻猪肉 / 储备 / 菜篮子`：`+25`
- 指标命中：`3000吨`：`+20`
- 业务类型一致：`reserve_supply`：`+15`

总分：`100`

预期结果：`evidence_auto`

## 数据模型变更

### 新增关联模式

为采购项目与预算项目的联动结果增加模式字段：

- `exact`
- `evidence_auto`
- `evidence_candidate`
- `none`

### 新增证据摘要

为每一条联动结果增加：

- `match_mode`
- `match_score`
- `match_reasons[]`
- `candidate_budget_project_ids[]`

### 候选关联存储

第一版建议新增独立表，例如：

- `budget_procurement_link_candidates`

字段至少包括：

- `id`
- `tenant_id`
- `procurement_project_id`
- `budget_project_id`
- `match_mode`
- `match_score`
- `match_reasons_json`
- `created_at`

这样可以避免把候选关系混入正式 `budget_project_id` 字段。

## 后端改造

### 1. 保留现有精确联动

继续使用当前 `v2_store.rs` 中的：

- `indicator_document_no`
- `project_catalog_id + unit`
- `unit + normalized project name`

### 2. 新增业务证据匹配函数

新增独立函数，输入：

- 采购项目
- 预算项目
- 预算摘要/summary_item
- 指标文号
- 项目名称
- 预算单位

输出：

- `score`
- `reasons`
- `mode`

### 3. 正式关联与候选关联分开写入

- `exact` / `evidence_auto`
  - 写入 `procurement_projects.budget_project_id`
  - 记录 `match_mode`
- `evidence_candidate`
  - 不写正式 `budget_project_id`
  - 仅写候选表

### 4. 预算详情的 linkage_summary 扩展

从现在的：

- `linked_procurement_projects`
- `unlinked_procurement_projects`
- `ambiguous_matches`

扩成：

- `exact_linked_procurement_projects`
- `evidence_auto_linked_procurement_projects`
- `candidate_procurement_projects`
- `unlinked_procurement_projects`
- `ambiguous_matches`

## 前端改造

### 采购详情页

新增展示：

- 关联模式
  - 精确关联
  - 证据自动关联
  - 证据候选关联
- 关联分数
- 证据摘要
  - 同单位
  - 命中关键词
  - 数量约束
  - 政策依据

### 预算详情页

新增展示：

- 已精确关联采购项目数
- 已证据自动关联采购项目数
- 候选采购项目数
- 候选关联项目列表

## 继续找官方主键材料的执行线

规则改造不替代外部找数。

继续搜索的目标文件类型：

- 项目库明细
- 指标文号明细
- 预算批复附表
- 冻猪肉储备承储、补贴或储备资金批复材料

优先范围：

1. 南京市商务局政府信息公开
2. 南京市财政局专项资金/预算批复公开
3. 市政府办公厅与菜篮子专项资金管理办法附件

如果后续找到主键材料，系统仍优先走 `exact`。

## 测试策略

### 单元测试

- 精确匹配仍保持原行为
- 证据评分命中阈值时返回 `evidence_auto`
- 分数在候选区间时返回 `evidence_candidate`
- 分数不足时不关联
- 不同单位即使同关键词也不能自动关联

### 集成测试

使用南京商务局真实样本构造 fixture：

- 预算：`菜篮子发展专项-肉菜储备`
- 采购：`冻猪肉政府性储备项目`

预期：

- 当前无主键材料时，命中 `evidence_auto`
- 详情页能看到证据摘要

### 回归测试

- 中山 `12345` 主键联动不回退
- 第一阶段采购模式不回退
- 第二阶段预算导入不回退

## 风险与约束

### 主要风险

- 公开数据名称相似但实际项目不同，误关联
- 词典过宽导致召回过高
- 候选关系与正式关系混淆

### 控制策略

- 单位不一致时不进入高可信证据匹配
- 第一版只用受控词典，不放开自由模糊匹配
- 明确区分 `exact`、`evidence_auto`、`evidence_candidate`
- 候选关系单独存储、单独展示

## 推荐结论

当前最合理的落地方案是：

1. 继续查南京商务局及财政相关公开附件，争取拿到 `项目库ID / 指标文号`
2. 同时在系统中新增 `evidence_auto + evidence_candidate` 双层业务证据匹配

这样既不放弃精确关联的标准，也能让政府公开数据在现阶段真正产生业务价值。
