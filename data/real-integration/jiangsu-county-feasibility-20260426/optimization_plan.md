# 江苏多县市真实数据测试后的优化计划

## P0：影响试点可信度的优先优化

1. 增加“公开统计指标”专用数据类型

当前将统计公报中的 GDP、财政收入、支出、金融余额、投资额等放入 `public_fiscal_summary` 能完成导入，但语义上仍和预算执行明细混在一起。建议新增或细化为：

- `public_fiscal_summary`：一般公共预算收入、税收收入、一般公共预算支出、重点科目支出。
- `public_statistical_indicator`：GDP、工业产值、固定资产投资、社会消费品零售总额、金融存贷款余额。
- `investment_review_summary`：送审金额、审定金额、核减金额、评审文号。

这样可以避免统计指标被预算规则误解，也方便做区域经济和财政承压分析。

2. 固化来源留痕

- 所有导入记录增加统一的 `source_url`、`source_title`、`source_published_at`、`source_capture_time`、`source_row`。
- 报告和案件详情页展示原始来源链接。
- 对 PDF、网页、采购公告分别保留解析版本号，避免来源页面更新后无法复现。

3. 补齐行政区划和单位归一化

- 建立江苏县市区字典：设区市、县市区、财政局、统计局、公共资源交易平台、政府采购平台。
- 将 `Kunshan City, Suzhou, Jiangsu` 等英文 region 映射为标准中文行政区划码。
- 对采购人、建设单位、财政局、统计局、发改委做机构别名归一化。

## P1：提高规则命中质量

4. 拆分采购阶段规则

本次 23 条采购记录全部命中“公告到合同到验收链条不闭合”，其中很多是正常的公告阶段项目。建议规则改成阶段感知：

- 公告阶段：标记为“后续链条待补充”，风险 Medium/Low。
- 合同已公告但无验收：标记为“履约验收缺失”，风险 Medium。
- 验收逾期或金额异常：标记为 High。
- 同采购人、同主题、短期多项目：再进入疑似拆包规则。

5. 优化拆包识别

- 引入项目名称相似度、采购人归一化、公告时间窗口、预算金额区间。
- 对老旧小区改造、道路养护、学校改造等天然分标场景建立白名单/合理分包模板。
- 输出“疑似拆包证据链”：项目编号、预算合计、公告日期、采购人、相似关键词。

6. 给财政公开数据增加轻量规则

公开统计公报适合做线索规则，而不是直接定性：

- 税收占比异常波动。
- 民生支出占比低于同类县市。
- 科技、环保、农林水、住房保障等重点科目大幅波动。
- 财政收入增长与 GDP/工业/投资增长背离。
- 高预算采购项目与公开重点支出科目缺少关联。

## P2：提高 PoC 交付能力

7. 做江苏县市专题看板

看板维度：

- 区域：苏州、无锡、常州、南京、盐城、泰州、镇江、南通等设区市及下辖县市区。
- 财政：一般公共预算收入、税收收入、一般公共预算支出、重点民生支出。
- 采购：公告数量、预算金额、闭环缺失数、疑似拆包数。
- 案件：线索数、分派数、超期数、整改状态。

8. 增加“一键复跑”测试脚本

本次目录中的 `build_jiangsu_county_dataset.mjs` 已能生成测试载荷。建议继续补一个正式测试脚本：

- 检查服务是否启动。
- 登录。
- 生成或读取 fixtures。
- 导入财政、采购、案件三类数据。
- 校验接收行数、拒绝行数、中文 roundtrip、规则命中数。
- 输出 Markdown 报告。

9. 报告模板产品化

生成标准报告：

- 数据来源清单。
- 数据质量检查。
- 导入结果。
- 规则命中。
- 案件线索。
- 公开数据局限。
- 需要试点单位补充的数据清单。

## P3：进入真实县区深度 PoC 的数据需求

公开数据足以做线索发现，但深度审计需要内部脱敏样本。建议优先选择一个材料较完整的县市，如东台、江阴、昆山、海安或江宁。

需要的内部样本：

- 预算指标：指标文号、预算单位、项目目录、功能分类、经济分类、指标金额、下达时间。
- 采购合同：采购项目编号、合同编号、供应商、合同金额、合同公告时间、验收时间。
- 国库支付：支付单号、收款方、支付金额、支付时间、预算指标引用。
- 会计凭证：凭证号、科目、摘要、金额、合同/支付单/附件引用。
- 整改台账：问题编号、责任单位、整改期限、复核状态。

建议验收标准：

- 至少 1 个县区、3 类业务域、3000 条以上脱敏明细。
- 公开线索和内部明细可做项目级关联。
- 高风险线索人工抽检准确率达到 90% 以上。
- 能完成“发现 -> 立案 -> 分派 -> 整改 -> 复核 -> 报告”的闭环演示。
