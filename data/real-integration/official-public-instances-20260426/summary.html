## 4. 进一步优化方案

- P0 正式来源采集自动化：把本次手工整理的中国政府采购网、江苏财政厅 PDF、江苏审计厅 PDF、南通财政局网页拆成可配置采集器，输出统一 source_evidence 和原始行定位。 原因：正式实例可以导入，但仍依赖人工摘录；下一轮要能用同一来源复跑并自动发现新增公告。
- P0 金额单位与异常值归一：增加元、万元、亿元、百分比、项目数量的单位字段和换算规则，对公告页显示为极小金额的记录标记单位复核。 原因：政府采购公告和财政报告存在不同金额口径，直接用字符串金额会影响拆分采购和波动规则评分。
- P1 采购阶段证据链：对公告、成交、合同三类已覆盖阶段建立项目级合并视图，缺失验收或支付时只输出补数建议，不形成强违规结论。 原因：公开数据通常缺少验收、支付、凭证，阶段感知规则需要继续防误报。
- P1 PDF 页码和条款回溯：source_evidence 增加 page、section、quote_hash 或 locator 字段，在报告中显示页码/段落位置。 原因：财政预算和审计报告 PDF 是关键正式证据，当前只有 URL 和行号，审计沟通时定位还不够细。
- P1 审计问题线索结构化：把审计工作报告的问题金额、责任主体、问题类型、需补充资料拆成专用字段，并和整改台账模板打通。 原因：审计报告适合生成 case seed，但后续闭环需要可匹配整改状态和补证清单。
- P2 公开样本验收基线扩展：将本次 49 条正式实例加入公开 PoC 基线，和南通 92 条、江苏多县市 164 条一起纳入一键复测差异报告。 原因：正式来源样本覆盖财政、采购、审计三类，应成为后续回归测试的一部分。
