# 江苏/南通真实数据测试后的优化计划

## P0：先修正会影响试点可信度的问题

1. 固化 UTF-8 导入链路

- 前端、API 文档、测试脚本统一使用 `application/json; charset=utf-8` 和 UTF-8 字节体。
- 增加中文 roundtrip 测试：采购项目名、单位名、文号、案件标题必须输入输出逐字一致。
- 对疑似 mojibake 文本增加导入前质量检查，发现 `å`、`æ`、控制字符等乱码特征时提示重新编码。

2. 增加来源留痕字段

- 财政、采购、案件种子导入均应保存 `source_url`、`source_title`、`source_published_at`、`source_capture_time`、`source_row`。
- 当前采购 payload 使用 `notice_url`，预算 payload 主要靠 `source_row` 和说明字段，建议统一成通用 `source_evidence` 结构。
- 报告页和案件详情页显示来源链接，方便试点单位回到政府公开页面核验。

3. 区分“公开预算摘要”和“预算执行明细”

- 当前 `budget_summary` 规则会把公开预算摘要与执行明细放在同一任务类型里处理，容易让用户误以为已完成预算执行审计。
- 新增 `public_fiscal_summary` 子类型的专用规则：同比波动、地区横向异常、功能科目缺失率、项目预算与公开采购计划是否一致。
- 对缺少内部凭证字段的数据，不触发强闭环类结论，只生成“待补充内部数据”的线索。

## P1：提升真实县区 PoC 的可行性

4. 建立县市区数据适配器

- 为南通市本级、海门、海安、如皋、通州、崇川、如东、启东分别维护来源配置：栏目 URL、标题规则、金额单位、日期格式、附件类型。
- PDF/网页/交易公告分开解析，解析结果先落到 staging 表，再由人工或规则映射进正式任务。
- 允许同一来源产生多类记录，例如预算报告同时产生财政摘要、民生项目、风险备注。

5. 建立项目联查键和模糊匹配

- 内部数据优先使用确定键：预算指标文号、项目目录 ID、采购项目编号、合同编号、支付单号、凭证号。
- 公开数据缺少确定键时，使用候选匹配：地区、采购人/建设单位、项目名称相似度、金额区间、发布时间窗口。
- 对每个联查结果给出置信度和证据，不把模糊匹配直接作为审计定性。

6. 优化采购规则

- `PROC-CHAIN-001` 对公告阶段项目应显示为“后续链条待补充”，避免全部显示成同一风险强度。
- `PROC-SPLIT-001` 增加项目名称相似度、采购单位归一化、预算金额窗口、公告时间窗口配置，减少同一工程合理分标造成的误报。
- 对老旧小区改造、道路养护、校园安全等常见工程建立行业模板，区分合理标段划分和疑似拆包。

## P2：增强产品展示和交付能力

7. 做南通专题区域看板

- 地图/列表维度覆盖市本级和县市区：海门、海安、如皋、通州、崇川、如东、启东。
- 指标包括公开预算收入/支出、采购公告金额、投资评审核减金额、案件线索数、高风险规则命中数。
- 支持按来源可信度、年度、领域、地区过滤。

8. 输出标准化试点报告

- 自动生成“数据来源、质量检查、规则命中、案件清单、待补数据清单、审计建议”六段式报告。
- 对每条发现附上来源链接、原始字段、系统归一化字段、规则解释和建议动作。
- 报告中明确标注“公开数据线索”和“内部数据确认结论”的区别。

9. 建立可重复测试脚本

- 保留本次 92 条真实样本作为 regression fixture。
- 增加一键测试：启动服务、登录、导入三类样本、检查接收行数、检查中文 roundtrip、导出摘要。
- 每次修改导入模型、规则或前端上传逻辑后，必须跑这套样本。

## P3：进入真实县区试点前的数据需求

建议选择海安或通州做第一个深度 PoC，因为公开资料中财政、投资评审、民生项目和采购线索较完整。

需要试点单位提供脱敏样本：

- 预算指标：指标文号、预算单位、项目目录、功能分类、经济分类、金额、下达时间。
- 采购合同：采购项目编号、合同编号、供应商、合同金额、公告/合同/验收时间。
- 国库支付：支付单号、收款方、支付金额、支付时间、预算指标引用。
- 会计凭证：凭证号、科目、摘要、金额、附件/合同/支付单引用。
- 整改台账：问题编号、责任单位、整改期限、状态、复核结论。

试点成功标准：

- 至少 1 个县区、3 类业务域、3000 条以上内部明细。
- 公开数据与内部明细能完成项目级关联，人工抽检准确率达到 90% 以上。
- 高风险发现能形成案件、分派、整改、复核闭环。
- 系统能生成一份可交付给财政/审计/监管部门的标准报告。
